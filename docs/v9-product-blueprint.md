# مالي v9 — إعادة بناء المنتج من الصفر هندسيًا

## القرار

الإصدار 9 ليس إعادة تلوين للنسخة الحالية. سيتم بناء تطبيق Android أصلي جديد داخل نفس المستودع مع الحفاظ على `applicationId = com.ha7n.mali` ومفتاح التوقيع الدائم حتى تصل النسخة الجديدة كتحديث رسمي عند جاهزيتها.

النسخة الحالية 8.x تبقى مستقرة على `main` أثناء التطوير. العمل الجديد يتم على الفرع `agent/v9-native-rebuild` ولن يُدمج قبل اكتمال البناء والاختبارات ومسارات الاستخدام الأساسية.

## الهدف الأساسي

تطبيق مالي شخصي محلي أولًا (Local-first) يفهمه المستخدم من أول مرة، ويجيب بسرعة عن أربعة أسئلة فقط:

1. كم أملك الآن؟
2. أين ذهبت أموالي هذا الشهر؟
3. كم بقي لي في خطتي الشهرية؟
4. ما الذي يحتاج انتباهي الآن؟

أي ميزة لا تساعد مباشرة في هذه الأسئلة لا تظهر في الواجهة الرئيسية.

## المبادئ المأخوذة من دراسة تطبيقات مالية ناجحة

- فصل مكان وجود المال (الحسابات) عن الغرض من المال (التصنيفات والخطة الشهرية).
- تقليل عدد التصنيفات الظاهرة افتراضيًا وإظهار الأكثر استخدامًا أولًا.
- جعل الميزانية الشهرية مرتبطة بالمصروفات الفعلية تلقائيًا بدل تسجيل "دفعة التزام" بشكل منفصل.
- الاعتماد على شاشة إضافة عملية واحدة وسريعة بدل نماذج متعددة.
- جعل التقارير بصرية ومباشرة، وليست صفحة أرقام كثيفة.
- إبقاء الإعدادات والميزات المتقدمة خارج المسار اليومي.

## تغيير مهم في نموذج الميزانية

مثال الوقود: إذا كانت خطة الوقود 350 ر.س في الشهر، فلا يوجد التزام منفصل يحتاج زر "دفعت".

كل عملية وقود مسجلة (50، ثم 60، ثم 70...) تُحسب تلقائيًا داخل خطة الوقود:

- الخطة: 350 ر.س
- المصروف حتى الآن: 180 ر.س
- المتبقي: 170 ر.س

هذا يقلل خطوة كاملة من الاستخدام ويمنع تكرار البيانات.

## تجربة الاستخدام الجديدة

### Onboarding

ثلاث خطوات فقط:

1. أضف أين أموالك: نقدي / بنك / محفظة.
2. أدخل الرصيد الحالي لكل حساب.
3. اختر ما تريد متابعته شهريًا (اختياري) مثل الوقود، المقاضي، المطاعم، الفواتير.

بعدها يدخل المستخدم للرئيسية مباشرة.

### الرئيسية

- بطاقة كبيرة: إجمالي ما تملكه الآن.
- ملخص الشهر: دخل / صرف / صافي.
- زر رئيسي واحد واضح: إضافة حركة.
- بطاقة "خطتي هذا الشهر" تعرض أهم 3 تصنيفات مع المتبقي وشريط تقدم.
- بطاقة "أين أموالي" تعرض الحسابات وأرصدتها.
- بطاقة "أين صرفت" تعرض توزيع المصروفات بصريًا.
- تنبيه واحد فقط عند الحاجة: اقتراب تجاوز خطة، رصيد منخفض، أو فاتورة مجدولة لاحقًا.

### إضافة حركة

تجربة واحدة بثلاثة أنواع:

- مصروف
- دخل
- تحويل بين الحسابات

ترتيب الحقول:

1. المبلغ (ريال كامل فقط)
2. النوع
3. التصنيف
4. الحساب
5. التاريخ (اليوم افتراضيًا)
6. ملاحظة اختيارية

يتم حفظ آخر التصنيفات والحسابات المستخدمة لتسريع الإدخال التالي.

### الخطة الشهرية

بدل شاشة الالتزامات المعقدة:

- كل تصنيف يمكن أن يملك حدًا/هدفًا شهريًا.
- المصروفات المسجلة تخصم منه تلقائيًا.
- حالات واضحة: ممتاز / قريب من الحد / تجاوز.
- تعديل الخطة لا يعدل العمليات السابقة.

### التقارير

- اتجاه المصروف خلال 6 أشهر.
- توزيع المصروف حسب التصنيف.
- مقارنة الدخل والمصروف.
- أكثر 5 تصنيفات صرفًا.
- اختيار فترة بسيط: شهر / 3 أشهر / 6 أشهر / سنة.

## التنقل

أربع وجهات سفلية فقط:

1. الرئيسية
2. الحركات
3. الخطة
4. التقارير

الحسابات والإعدادات والنسخ الاحتياطي تفتح من أعلى الرئيسية ولا تأخذ مكانًا دائمًا في شريط التنقل.

## التصميم البصري

- Material 3 أصلي.
- اتجاه RTL كامل.
- ألوان محايدة هادئة مع ألوان دلالية فقط:
  - أخضر = دخل / حالة جيدة
  - أحمر = صرف / تجاوز
  - كهرماني = تنبيه
  - أزرق = خطة / معلومات
- الوضع الداكن من نظام Android ومن داخل التطبيق.
- لا نعتمد على Emoji كأيقونات واجهة أساسية؛ تستخدم Material Icons لتناسق أفضل.
- حجم لمس لا يقل عن 48dp للعناصر التفاعلية.
- الرسوم البيانية بسيطة وغير مزدحمة.

## البنية التقنية

### Android أصلي

- Kotlin
- Jetpack Compose + Material 3
- Single Activity
- ViewModel + StateFlow + Unidirectional Data Flow

### البيانات

- Room/SQLite للبيانات المالية المنظمة.
- DataStore لإعدادات العرض والتفضيلات الصغيرة.
- جميع المبالغ `Long` بالريال الكامل، لا Double ولا هللات.
- Repository layer بين الواجهة وقاعدة البيانات.

### الكيانات الأساسية

- Account
- Transaction
- Category
- MonthlyPlan
- AppSetting

لا يتم إنشاء جداول منفصلة للالتزام والبنزين والأقساط إلا إذا ظهرت حاجة حقيقية لاحقًا. نبقي النموذج الأساسي صغيرًا ومفهومًا.

## الحفاظ على بيانات 8.x

عند أول تشغيل لـ v9:

1. نقرأ نسخة الحالة القديمة من SharedPreferences (`mali_finance_local` / `finance_state_v1`) إن وُجدت.
2. نستورد الحسابات والعمليات والتصنيفات والخطط التي يمكن تحويلها بأمان.
3. نحفظ JSON القديم كاملًا كأرشيف محلي قبل إنهاء الترحيل.
4. نضع علامة `legacy_migration_completed` حتى لا يتكرر الاستيراد.
5. يبقى الاستيراد اليدوي من ملف JSON موجودًا كخطة إنقاذ.

## النسخ الاحتياطي

- تصدير JSON يدوي.
- استيراد JSON مع فحص الإصدار والتحقق من صحة البيانات.
- Android Auto Backup لقاعدة Room وDataStore مع استثناء الملفات المؤقتة.
- لا يتم تخزين مفاتيح توقيع أو أسرار داخل التطبيق.

## شروط الدمج إلى main

لا يتم دمج v9 قبل تحقق التالي:

- Build Release ناجح بالتوقيع الدائم.
- اختبارات وحدة لحساب الأرصدة والخطة الشهرية والتحويلات.
- اختبارات Room migrations.
- اختبارات Compose لمسارات: onboarding، إضافة مصروف، إضافة دخل، تحويل، تعديل، حذف، خطة شهرية، تقرير.
- اختبار ترحيل بيانات 8.x.
- اختبار الوضع الداكن وRTL وSafe Areas.
- اختبار فتح التطبيق وإغلاقه وإعادة تشغيله مع بقاء البيانات.
- اختبار تصدير واستيراد النسخة الاحتياطية.

## ما لن نفعله

- لن نبني WebView جديدًا.
- لن نعتمد على Vercel أو الإنترنت لتشغيل Android.
- لن نعيد كل الميزات السابقة لمجرد أنها كانت موجودة.
- لن نضع عشرات الخيارات في الرئيسية.
- لن ندمج الفرع الجديد إلى main قبل أن يصبح فعليًا أفضل من 8.x في الاستخدام والاستقرار.
